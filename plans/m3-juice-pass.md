# M3 — Juice Pass: Trail, Particles, Shake, Haptics, SFX, Bonus Scoring, Zones

**Status: Done** (implemented + unit-tested; SFX character and effect timing
await on-device tuning. Step 7's graze slow-mo was skipped — revisit only if
grazes feel unrewarded after playtesting.)

> Pre-M3 changes folded in after discussion: crash deaths are restored (the
> no-crash experiment is over) and a short dashed tangent **aim line** ships
> with this milestone — it fixes the game's confusion-difficulty so crashes
> can stay. Combo window tightened to half a revolution. Graze redefined back
> to the design doc's intent (see below).

## 1. Goal

Make every run look and sound like a postable clip. After M3 the game has: a
comet trail that intensifies with your combo, particle bursts on capture and
death, screen shake and impact flash on death, squash/stretch on release,
haptics and pitched synth SFX on every event, combo/graze/perfect bonus
scoring, and zone transitions (background hue shift + zone name flash) every
20 planets. Mechanics are untouched — M3 changes how the game _feels_, not how
it plays.

## 2. Scope

**In:**

- Ball comet trail (length/brightness scale with combo)
- Squash/stretch on release
- Particle bursts: capture pop, graze sparks, death shatter
- Impact flash + screen shake on death
- Combo multiplier ("hot streak": release within first revolution)
- Graze bonus (near-miss outside a ring) and perfect-capture bonus
- Zone system made visible: background palette shift + zone name flash
- Haptics (release / capture / graze / death / zone)
- Minimal synth SFX, pitch rising per combo link (generated by a repo script)
- HUD: combo indicator; score becomes points (see decision below)
- Optional micro slow-mo on graze (last step; cut first if feel is off)

**Out (explicitly):**

- Home screen, death card redesign, share button, settings, persistence (M4)
- Ads, "continue" flow (post-launch)
- Black hole, moving planets, asteroids (v1.5 / later dials)
- Skins/unlockables (v2 parking lot)
- Parallax starfield (nice-to-have; only if trivial while touching background)

## 3. Design decisions

### Two numbers: planets passed vs score

Until now `score == planetsPassed`. Bonuses break that, so they split:

- **`planetsPassed`** keeps driving every difficulty dial and the zone index —
  the game never gets harder because you scored stylishly.
- **`score`** becomes points: capture is worth `1 × combo multiplier`, plus
  flat graze/perfect bonuses. The big HUD number is **score**.
- Starting values (constants, tune later): capture +1 × multiplier; graze +2;
  perfect +3; multiplier = 1 + comboLinks, capped at ×5.

> **Flag for sign-off:** the design doc's "+1 per planet" reading of the big
> number changes — with bonuses, score ≈ 1.5–3× planets. The alternative
> (big number stays planet count, bonuses shown separately) reads worse in
> clips. Recommend: big number = points.

### Combo ("hot streak")

- Engine accumulates `revolutions` (angle swept / 2π since capture).
- Release with `revolutions < 0.5` → `comboLinks += 1`. **Half** a revolution,
  not a full one: orbit decay already forces release within ~a revolution, so
  a full-rev window would make the multiplier permanently-on. Half a rev is a
  real choice — take the first usable tangent or wait for the ideal one and
  lose the streak.
- The streak resets to 0 **the moment the window closes** while still
  orbiting (trail visibly cools while you hesitate — telegraphed, clip-friendly).
- Death obviously resets. Multiplier = `clamp(comboLinks, 1, COMBO_CAP=5)` —
  a single quick hop is ×1; chains of 2+ show ×2, ×3…

### Graze and perfect (crash deaths restored)

With crash deaths back, the design doc's original graze intent works again —
rewarding _risky proximity to the surface_:

- **Graze** = captured with closest approach within `GRAZE_MARGIN` (~8px) of
  the planet surface — a few pixels from a crash. Sparks + bonus.
- **Perfect** = captured with closest approach within the middle ~25% of the
  capture band — the precision reward. Perfect beats graze if both apply
  (only possible on very narrow late-game bands).

### Effects architecture: timestamps + pure functions, no event queues

The sim already runs on the UI thread with a no-allocation frame contract, so
effects piggyback on it:

- Engine stamps discrete events into `GameState`: `lastReleaseAt`,
  `lastCaptureAt` + `capturePos` + `captureKind` (normal/graze/perfect),
  death time (exists; ball position doubles as death position), and
  `zoneChangedAt`. Replacing a small object on a discrete event is fine;
  nothing allocates per frame.
- **Every visual effect is a pure function of `(state, now)`** rendered via
  Skia derived values — no particle arrays are simulated. A burst renders N
  particles whose positions are computed from `(origin, elapsed, particle
index)` with a per-burst seed: deterministic, allocation-free, and worklet-
  friendly. Shake is a decaying sinusoid of `time - deathTime` applied to the
  existing world-translate group. Flash is an opacity curve on a full-screen
  rect. Squash/stretch is a scale matrix from `time - lastReleaseAt`.
- **Trail** needs no buffer at all: recent path history is _analytic_ — a
  straight line back along the velocity while flying, an arc back along the
  orbit while orbiting. Each trail dot derives its position from the current
  state directly (also sidesteps mutating shared-value internals, which the
  worklets runtime freezes). Opacity scales with combo heat.
- Haptics/SFX are JS-side: `useAnimatedReaction` on the event timestamps →
  `runOnJS` into an effects module. One frame of latency is imperceptible.

### Zones (visible)

- `zoneIndex = floor(planetsPassed / 20)` already exists in `difficulty.ts`.
- `src/rendering/zones.ts`: per-zone background gradient palettes (cycled) and
  placeholder zone names (VOID / EMBER FIELD / VIOLET DEEP / FROSTBITE /
  GOLDEN WASTES / CRIMSON DRIFT — **user should rename at will**, it's a
  string array).
- Background gradient cross-fades between palettes over ~1.5s from
  `zoneChangedAt` (pure interpolation in a derived value).
- Zone name flashes big-and-fading in the HUD (React state via reaction —
  discrete event, allowed re-render). Planet colors stay per-planet for now;
  tinting planets per zone is a later flavor pass.

### SFX without an audio designer

- `scripts/generate-sfx.ts` (bun) synthesizes tiny WAVs into `assets/sfx/`:
  release blip, capture pluck, graze spark, perfect chime, death boom, zone
  swell. Sine/triangle + exponential decay envelopes — the "minimal synth"
  look the design doc asks for, regenerable and tweakable in code.
- `src/audio/sfx.ts` preloads players via `expo-audio`; combo pitch rise uses
  `playbackRate = 2^(comboLinks × semitones/12)` on the capture pluck.
- Haptics via `expo-haptics`: light (release), medium (capture), soft tick
  (graze), heavy + notification (death), success (zone).
- Mute/settings toggles are M4; M3 ships sound-on.

### State/type changes

`GameState` gains: `planetsPassed`, `comboLinks`, `revolutions`, `zoneIndex`,
`lastReleaseAt`, `lastCaptureAt`, `captureKind`, `capturePos`,
`zoneChangedAt`, `effectSeed`. All primitives or replaced-on-event objects —
the copy-then-mutate frame contract holds. The effect seed is a hash (never a
consumed rng draw), so generation determinism is independent of captures.

## 4. Implementation steps (game stays playable after each)

1. **Scoring engine** — planetsPassed/score split, combo tracking, graze +
   perfect detection, event timestamps; HUD shows score + combo multiplier.
   Touches: `types.ts`, `constants.ts`, `engine.ts`, `difficulty.ts` (reads
   planetsPassed), `GameScreen.tsx`, tests.
2. **Trail + squash/stretch** — ring buffer shared value, trail rendering,
   release deformation. Touches: `GameScreen.tsx`, `GameCanvas.tsx`.
3. **Particles + death drama** — pure-function burst renderer (new
   `src/rendering/effects.ts`), capture pop, graze sparks, perfect pulse,
   death shatter + flash + shake, ball hidden on death (already) with shatter
   in its place. Touches: `effects.ts`, `GameCanvas.tsx`.
4. **Zones visible** — `rendering/zones.ts`, background cross-fade, zone name
   flash in HUD. Touches: `zones.ts`, `GameCanvas.tsx`, `GameScreen.tsx`.
5. **Haptics** — effects module + reactions. Touches: new `src/effects/haptics.ts`,
   `GameScreen.tsx`.
6. **SFX** — generation script, assets, audio module, combo pitch. Touches:
   `scripts/generate-sfx.ts`, `assets/sfx/`, new `src/audio/sfx.ts`,
   `GameScreen.tsx`.
7. **(Optional) graze slow-mo** — `timeScale` dip to ~0.35 for 60ms on graze,
   recovering over ~150ms. Cut without ceremony if it feels like lag.

Worklet reminder: callees before callers in every engine/rendering module —
same constraint that hard-crashed M1.

## 5. Testing & acceptance criteria

- `bun test` green with new suites: combo accrual/reset (release timing,
  revolution completion, death), graze detection (one per planet per flight,
  margin edges), perfect window, score arithmetic vs planetsPassed, zone
  boundary timestamps.
- On device, 3+ runs past planet 40:
  - steady 60fps with trail + bursts + shake active (no allocation growth);
  - every event visibly/audibly distinct: release, capture, graze, perfect,
    zone change, death — a first-time viewer can tell them apart;
  - combo trail intensity readable in a muted vertical clip;
  - zone transition obvious ("the background changed") without blocking play;
  - death reads dramatic: flash + shatter + shake + thud land together.
- Record one 15-second screen capture and check it actually looks postable —
  this is the design test the whole project optimizes for.
